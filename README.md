# Визуализация графа зависимостей Alpine Linux

Практическая работа № 2, вариант 16. Программа читает APKINDEX.tar.gz,
строит граф зависимостей рекурсивным DFS и сохраняет его описание на D2
и изображение SVG. Изображение открывается в браузере по умолчанию.

## Запуск

Нужны Python 3.11 или новее и команда `d2` в PATH. Сборка не требуется.
Для доступа к удалённому индексу нужно подключение к сети.

```powershell
.\run.bat config.toml
python src/main.py examples/zlib.toml
python src/main.py examples/xz.toml
python src/main.py examples/curl.toml
python src/main.py tests/data/diamond.toml
python src/main.py tests/data/cycle.toml
python -m unittest discover -s tests -v
```

Команда создаёт `out/<пакет>.d2` и `out/<пакет>.svg` относительно текущей
папки. Стрелки направлены от пакета к его зависимости.

## Настройки TOML

| Ключ | Значение |
| --- | --- |
| `package` | Имя пакета APK или имя из больших латинских букв в тестовом режиме |
| `repository` | URL каталога Alpine, URL архива APKINDEX.tar.gz или путь к тестовому файлу относительно TOML |
| `test_mode` | При `true` читается тестовый файл |
| `ascii_tree` | При `true` дополнительно печатается ASCII-дерево |

Тестовый файл содержит записи вида `A: B C`. Для каждого пакета нужна
собственная строка. Пустой список справа означает отсутствие зависимостей.
Метка `(cycle)` указывает на возврат к предку, `(shown)` — на уже
раскрытый узел. В обоих случаях граф сохраняет исходное ребро.

## Модули

- `config.py` читает TOML и проверяет четыре параметра.
- `apk_index.py` скачивает архив и читает записи P, V, D и p из APKINDEX.
- `repository.py` читает тестовые списки или сопоставляет требования
  APK с пакетами и предоставляемыми ими модулями.
- `graph.py` обходит только достижимые вершины, отмечает циклы и
  вычисляет порядок завершения обхода.
- `visualize.py` формирует D2, ASCII-дерево и вызывает рендерер.
- `main.py` связывает эти операции и сообщает об ошибках в stderr.

Анализ использует один индекс. Поддерживаются требования без версии и
с точным равенством версии. При нескольких поставщиках приоритет у
пакета с совпадающим именем. Неоднозначные требования, отсутствующие
пакеты и диапазоны версий остаются отдельными вершинами. Отрицательные
требования в граф зависимостей не включаются. Установленные пакеты,
условные установки и полный выбор совместимых версий обрабатывает
штатный `apk`.

## Этапы

История Git содержит пять этапов. Первый коммит выводит настройки,
второй — прямые зависимости, третий — списки смежности. Четвёртый
выводит зависимости в порядке завершения DFS. Пятый визуализирует граф.
Для воспроизведения промежуточного этапа откройте соответствующий коммит
из `git log --oneline`.

## Проверка со штатным apk

Использован apk-tools 2.12.7 и тот же APKINDEX Alpine 3.14 (main, x86_64).
В изолированной системе с пустой базой установленных пакетов
`apk add --simulate python3` показал 16 зависимостей в порядке DFS.
Последним apk указал сам python3.

Команды `apk dot zlib`, `apk dot xz` и `apk dot curl` дали соответственно
1, 3 и 21 ребро. После сопоставления узлов по именам пакетов множества
рёбер совпали. В DOT у узлов есть версии, а на рёбрах виртуальных
зависимостей — исходные имена требований из APKINDEX.
